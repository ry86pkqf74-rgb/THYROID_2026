### Workflow patterns to memorialise

- **Reset-then-rebuild discipline**: when Logan rejects a build, write a `<script>_reset_<version>.py` one-shot that snapshots-and-drops, then rebuild from clean. Avoids `ALTER TABLE ... ALTER COLUMN ...` accumulation drift.
- **CHECKPOINT pause discipline**: explicit `--skip-strip` flag + marker-file gate (`.invasion_cpm_repoint_applied` etc.) for human-in-the-loop sign-offs between build and destructive operations.
- **3-commit cascade**: build → CPM repoint → strip. Each commit independently verifiable. Don't bundle.
- **PHI sidecar protocol**: when diagnostic queries need to surface clinical text (evidence spans), write to a sidecar markdown file with explicit `⚠️ CONTAINS PHI — do NOT commit to git` header, surface in chat for review, delete after fix is green. Never stage or commit. (Used during v3-iter-2 LLM ladder bug investigation; sidecar deleted before commit `b0a03b0`.)

### Gotchas to add to project memory

- **`drop_view_alter_table_view_dependents.md` rule**: ALTER TABLE DROP COLUMN does NOT cascade-refresh dependent views in DuckDB/MotherDuck. Step 7 cascade strip MUST `CREATE OR REPLACE VIEW` for every view that touches the affected table after the drop.
- **Heuristic CPM feeder mapping is noisy**: the `git grep` + name-pattern heuristic in Step 5 finds CPM cols with related names but many are derived from different sources (note_entities joins, lab queries, etc.). Always type-check + investigate before repointing — the original 16 in the repoint plan resolved to only 8 actual BOOL feeders (the other 8 were heuristic false-positives skipped explicitly).
