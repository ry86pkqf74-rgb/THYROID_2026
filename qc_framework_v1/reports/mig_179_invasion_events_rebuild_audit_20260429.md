## Executive summary

This lane patches the existing invasion canonical builder instead of rebuilding the system from scratch. The root defect is that LVI patterns in raw synoptic pathology can represent lymphatic invasion even when the current feeder emits only vascular rows or misses the row entirely. The most important case is combined CAP text such as `Lymph-Vascular Invasion: Present`, which must produce both:

- `vascular_microscopic`, `finding_status='present'`
- `lymphatic_microscopic`, `finding_status='present'`

The patch adds a supplemental `path_synoptics` re-extraction CTE to `scripts/363_invasion_canonical.py` and authors the governed apply artifact `qc_framework_v1/migrations/179_canonical_invasion_events_v1_rebuild_lvi_20260429.sql`.

## Script changes authored

### `scripts/363_invasion_canonical.py`

1. Added `NULLISH_VARCHAR_TOKENS` so `n/a`, `null`, `nan`, and empty values are treated as missing rather than negative events.
2. Added quantitative `< N per 2mm2` present-state handling in `_status_case_sql()`.
3. Added `_nonnull_norm_predicate_sql()` and applied it to generic VARCHAR extraction CTEs.
4. Added new `MODALITY_PLAN` kind: `path_synoptics_lvi_reextract`.
5. Added `_build_cte_path_synoptics_lvi_reextract()` to unpivot tumor slots 1-5 from `main.path_synoptics` and emit supplemental LVI events.
6. Wired the new kind into `_build_step_1_sql()` with explicit column-gate checks.

The patch preserves the existing script-363 infrastructure and does not alter `canonical_patient_master.lvi_*` columns.
